Design notes. One PATIENT (환자) links to its HEALTH_EXAM, LIFESTYLE and DIAGNOSIS records through patient_id (FK → PK). Each child table keeps its own surrogate PK from an Oracle sequence, so the design supports a 1 : N relationship (in the current BRFSS dataset every patient has exactly one record each). ANALYSIS_RESULT (분석결과) stores the SQL analysis outputs and holds no FK — it is written by the analysis queries, not linked to a patient. Constraints in the schema: PRIMARY KEY, FOREIGN KEY, NOT NULL, and CHECK (e.g. diabetes_status IN (0,1,2), sex IN (0,1), bmi BETWEEN 10 AND 60).
